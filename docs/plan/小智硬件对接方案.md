# 小智硬件对接方案（xiaozhi-esp32 → 心晴伙伴系统）

> 状态：方案定稿 · 待硬件到位后联调
> 结论：小智套件（ESP32-S3 复刻，可刷开源固件）是当前最合适的桌宠载体，
> 架构与系统同构（硬件终端 + 服务器大脑），接入方式为「部署开源 xiaozhi-server
> + 业务接口适配模块」，不改固件、不改后端核心。

---

## 1. 目标

把「小晴」从网页搬进实体桌宠：机器人麦克风收音 → 系统 AI 思考（量表/危机协议全生效）
→ 机器人喇叭播答 + 屏幕做表情。学生像跟宠物说话一样完成心理评估对话。

## 2. 架构

```
┌──────────────┐  WiFi / WebSocket(Opus 音频)  ┌─────────────────────┐
│ 小智硬件终端 │ ────────────────────────────> │  xiaozhi-server      │
│ ESP32-S3     │  <─────────────────────────── │  （开源，部署在电脑/服务器）│
│ 麦+喇叭+屏    │                               └──────────┬──────────┘
└──────────────┘                                          │ 文本对话
                                               ┌──────────▼──────────┐
                                               │ 业务接口适配模块      │
                                               │ （xiaozhi 的 LLM 环节 │
                                               │   调我们后端对话接口） │
                                               └──────────┬──────────┘
                                                          │
                                    ┌─────────────────────▼─────────────────────┐
                                    │ 心晴伙伴后端（现有，不改）：                  │
                                    │ 三智能体（调度/对话/抽取）· 量表进度 · 危机上报 │
                                    │ 学生/老师/家长三端 · 情绪手账                  │
                                    └───────────────────────────────────────────┘
```

要点：
- **音频链路**：xiaozhi-server 原生负责 ASR（语音转文字，阿里云百炼 Paraformer）
  与 TTS（文字转语音，百炼 CosyVoice）；Opus 编解码在 xiaozhi-server 内完成，我们不动。
- **大脑链路**：xiaozhi-server 的 LLM 环节是模块化的，可替换为「业务接口适配模块」，
  即把 xiaozhi 发来的文本发给心晴伙伴后端 `/api/dialog/message`，把 AI 回复文本
  送回 xiaozhi-server 交给 TTS 播放。
- **关键收益**：小晴人设、PHQ-A/GAD-7/ASQ 量表推进、关键词危机兜底、心理老师上报、
  家长通知——全部业务逻辑**零改动**生效，因为硬件只是换了输入输出方式。

## 3. 两条路径对比

| | 路径 A：xiaozhi-server + 适配模块（推荐） | 路径 B：改固件直连 Qwen Realtime |
|---|---|---|
| 工作量 | 部署 + 配置 + 1 个适配模块（约 1~2 周） | 固件层实现 OpenAI Realtime 协议（数周，社区无先例） |
| 固件 | 刷官方开源固件，只需配置服务器地址 | 需要持续维护自改固件 |
| 卖家售后 | 不需要（开源社区支持） | 帮不上 |
| 语音体验 | ASR/TTS 分离，延迟约 1~2s，支持打断 | 理论延迟更低，但风险高 |
| 结论 | ✅ 采用 | ❌ 备选 |

## 4. 路径 A 落地步骤

1. **部署 xiaozhi-server**（开源仓库：github.com/xinnan-tech/xiaozhi-esp32-server，
   有 Docker 镜像）：跑在你的电脑或任何服务器上，小智固件通过 WiFi 连它。
2. **配置语音**：server 配置里选阿里云百炼（DashScope）的 ASR（Paraformer）与
   TTS（CosyVoice），复用现有 `DASHSCOPE_API_KEY`。
3. **写业务接口适配模块**（本项目新增一个模块）：
   - 输入：xiaozhi-server 传来的用户文本
   - 输出：心晴伙伴对话接口的 AI 回复文本
   - 复用现有接口：`POST /api/dialog/message`（文本模式）+ 会话历史接口；
     学生身份用测试学生（或从设备绑定关系读取），老师端/家长端照常工作
4. **表情指令（二期）**：小屏表情可先用 xiaozhi 现有 emoji/状态灯能力；
   需要「小晴专属表情」时，走 xiaozhi 的 MQTT 控制通道下发简单指令即可。
5. **联调验证清单**（硬件到手后逐项打勾）：
   - [ ] 小智能连上自部署 server（WiFi 配网成功）
   - [ ] 对话走的是心晴伙伴后端（回复里出现小晴人设与量表问题）
   - [ ] 打断体验（说到一半能被插话）
   - [ ] 危机句 → 老师端出现上报提醒
   - [ ] 家长端能收到对应通知

## 5. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 卖家固件虽可刷开源但音频板有杂音/兼容问题 | 先买最低配验证；不行退换，方案不变 |
| xiaozhi-server 版本与百炼接口变动 | 锁定版本部署（文档记录版本号） |
| 局域网内延迟偏高（>2s） | 将 server 部署在与机器人同一路由器的电脑上 |
| 现场无 WiFi | 电脑开热点供机器人连接（答辩标配做法） |

## 6. 与大挑叙事的关系

这套方案正好支撑「硬件落地」的故事：网页三端（已交付）→ 桌宠实体（小智套件）
→ 未来 ElectronBot 定制外壳。答辩可讲：软硬解耦、终端-云端架构、安全协议在云端
强制执行（危机上报不依赖硬件能力），这是心理安全类产品的加分表述。
